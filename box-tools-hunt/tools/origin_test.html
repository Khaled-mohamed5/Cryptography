Reading the results

Readable response (a successful cors fetch) is the strong result: this origin can both drive the server and read what comes back — session data, file lists, tokens.

Side effect fired is the one people wrongly dismiss. A plain GET with no custom headers is never preflighted. The browser will refuse to hand you the response body, but the request still arrived and the server still acted on it. If Box Edit downloads and opens a file as a result, the response body is irrelevant — that is the vulnerability. The no-cors, image and form tests below exist purely to prove delivery, so a "blocked" readable result plus a timing/behaviour signal here is still a valid, reportable finding.

Everything refused means the server checks the Origin. Next step is not to give up but to attack the check itself: null origin from a sandboxed iframe, suffix confusion, scheme downgrade, and DNS rebinding against the Host header. probe_com_server.py covers those from outside the browser.
